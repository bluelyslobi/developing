  - 판매하기 모달: 카테고리/상품명/가격/상태/지역/설명/사진 → Firestore 저장

===================================================
  Firestore 보안 규칙 실제 배포 + 버그 2건 해결 (2026-07-27)
===================================================

  배경: 트래블시커 개발기 블로그 시리즈(아래 섹션) 스크린샷 촬영 중
        발견/해결

  1) Firestore 규칙 만료 → 앱 전체 먹통
  ----------------------------------------
  - 증상: 앱 전체가 "Missing or insufficient permissions" 에러로 동작 불가
  - 원인: Firestore가 2026-06-21 테스트 모드로 생성되어 30일 후(~07-21)
    자동 만료. 로컬에 작성만 해두고 실제 배포는 안 했던 firestore.rules가
    이 시점까지 한 번도 반영된 적 없었음
  - 해결: firebase login(사용자 직접 실행) →
    `firebase deploy --only firestore:rules` 로 배포 ✅
  - 남은 것: storage.rules는 아직 미배포 (아래 참고)

  2) 채팅 메시지 전송 후 화면에 안 뜨는 버그
  ----------------------------------------
  - 증상: 메시지 전송 시 입력창은 비워지는데 대화창에 전혀 표시 안 됨
  - 원인: firestore.rules의 chats/{chatId}/messages 읽기 규칙이
    get(.../chats/$(chatId)).data.participants를 무조건 호출하는데,
    채팅방 문서가 아직 없는 상태(첫 메시지 전송 전)에서 ChatScreen.js가
    미리 붙여두는 onSnapshot 리스너가 이 get() 실패로 즉시
    permission-denied를 받아 죽어버림 → 이후 sendMessage()가
    실제로는 채팅방 문서+메시지를 잘 저장해도, 이미 죽은 리스너는
    다시 살아나지 않아 화면엔 영원히 안 뜸
  - 해결: 규칙을 `!exists(부모문서) || 기존조건` 형태로 수정 →
    부모 문서가 없을 때는 빈 목록으로 허용(리스너 생존) → 나중에
    문서가 생기면 같은 리스너가 자동으로 새 메시지를 받아옴
  - 덤 수정: ChatScreen.js의 onSnapshot 에러 핸들러가 console.error를
    남기도록 고쳐서 앞으로 이런 종류의 버그가 조용히 묻히지 않게 함
  - `firebase deploy --only firestore:rules`로 배포, 에뮬레이터에서
    테스트 계정 2개로 재현 후 실시간 전송까지 확인 ✅

  3) 미해결 — Firebase Storage 콘솔 설정
  ----------------------------------------
  - storage.rules 배포 시도 시 "Firebase Storage has not been set up" 에러
  - Firebase 콘솔(https://console.firebase.google.com/project/
    travelshare-b6659/storage)에서 최초 1회 "시작하기" 클릭 + 위치 선택
    (서울/asia-northeast3 권장) 필요 — 콘솔에서 사람이 직접 눌러야 하는
    단계라 아직 미완료
  - 이게 끝나야 storage.rules 배포 가능

===================================================
  Firestore 스키마 (전체)
===================================================

  users/{uid}
    uid, email, nickname, createdAt,
    postCount, likeCount, followCount

  posts/{id}
    uid, author, avatar, destination, title, content,
    image, likes, likedBy[], comments, createdAt
    └ comments/{id}: uid, author, avatar, text, createdAt

  products/{id}
    uid, author, title, price, category, condition,
    location, description, image,
    status('판매중'|'판매완료'), createdAt

  packages/{id}
    uid, author, title, destination, duration, price,
    originalPrice, discount, tags[], includes[],
    schedule[], image, rating, reviews, createdAt
    └ reviews/{id}: uid, author, rating(1-5), text, createdAt

  chats/{chatId}
    participants[], productId, productTitle,
    lastMessage, lastMessageAt
    └ messages/{id}: uid, text, createdAt

  reservations/{id}
    uid, userNickname, packageId, packageTitle,
    packageImage, price, destination, duration,
    status('예약중'), createdAt

  reports/{id}
    uid, targetId, targetType('post'|'product'|'package'),
    reason, createdAt

  chatId 생성 규칙:
    [buyerUid, sellerUid].sort().join('_') + '_' + productId
    participants[0] = buyer, participants[1] = seller
