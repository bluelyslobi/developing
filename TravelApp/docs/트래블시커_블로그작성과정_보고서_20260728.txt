===================================================
  작성 과정 (진행 순서)
===================================================

  1) 시리즈 구성 기획
     - 전체 개발 히스토리(초기 구조 → Firebase 연동 → 소통기능 →
       개명 사연 → 컨셉 방향전환)를 6개 에피소드로 분할
     - 각 화마다 하나의 뚜렷한 사건/주제를 중심으로 구성
       (기술 나열이 아니라 "이야기" 형식 유지)

  2) 원고 작성 (.md 6편)
     - 톤: 1인칭 경험담, 개발 강의체 지양
     - 각 화 말미에 "다음 화 예고" 문구로 연결성 부여
     - 저장 위치: TravelApp/docs/blog/*.md

  3) 스크린샷 촬영 준비
     - 실제 앱 화면을 캡처해 글에 곁들이기로 결정 (텍스트만으로는
       설득력 부족 판단)
     - 에뮬레이터(Pixel_8 AVD)에 테스트 계정 2개 신규 생성:
       blogtest2026@example.com(닉네임 blogtest),
       buyer2026test@example.com(닉네임 buyertest), 비밀번호 test1234
     - 중고거래 테스트 상품 "TravelCarrier"(₩80,000)도 등록해
       채팅/거래 화면 캡처용으로 사용

  4) 촬영 중 발견한 장애물 → 해결
     - 장애물 A: 캡처 도중 앱 전체가 "Missing or insufficient
       permissions" 에러로 먹통이 됨
       → 원인 규명: Firestore가 2026-06-21 테스트 모드로 생성돼
         30일 후(~07-21) 자동 만료. firestore.rules는 로컬에
         작성만 돼 있고 실제 배포된 적이 없었음
       → 조치: firebase login(사용자 직접) →
         `firebase deploy --only firestore:rules` 배포로 해결
     - 장애물 B: 채팅 화면 캡처 중 메시지를 보내도 대화창에 안 뜨는
       버그 발견
       → 원인 규명: 채팅방 문서가 없는 최초 상태에서 보안규칙의
         get() 검사가 실패 → onSnapshot 리스너가 즉시 죽음 →
         메시지는 실제로 저장돼도 이미 죽은 리스너가 화면을 못 갱신
       → 조치: 보안규칙 수정(부모 문서 없으면 빈 목록 허용) 후
         재배포, 에뮬레이터에서 실시간 전송까지 재현 확인
     - 결과적으로 블로그용 스크린샷을 찍으려다가 실제 서비스에
       영향 있는 버그 2건을 조기에 발견·수정하게 됨 (예상 밖 성과)

  5) 최종 캡처 완료
     - 홈/커뮤니티 목록/커뮤니티 글쓰기/중고거래 목록/패키지
       목록·상세/프로필 로그인·회원가입·마이페이지/채팅 화면 등
       9장 저장 → TravelApp/docs/blog/shots/

  6) 원고에 스크린샷 배치 및 마무리
     - 6편 원고 + 스크린샷 세트 완성, 초안 상태로 보관
